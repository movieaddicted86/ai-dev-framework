# Playbooks

Step-by-step procedures for recurring situations. The lead follows them; tasks reference them.

| Playbook | When |
|---|---|
| [project-start.md](project-start.md) | a new project adopts the framework |
| [audit-to-refactoring.md](audit-to-refactoring.md) | baseline audit, before a feature wave, every few months |
| [behaviour-preserving-refactoring.md](behaviour-preserving-refactoring.md) | any refactoring task: the evidence kit (baseline, pins, golden captures) |
| [external-review-intake.md](external-review-intake.md) | an independent review/audit arrives: verify, rank, package |
| [ui-rebuild.md](ui-rebuild.md) | rebuilding a user interface: design + mockup first, hooks before markup, layered tasks |
| [human-acceptance-test.md](human-acceptance-test.md) | after each UI group: a planned hands-on test by the decider, findings list, triage |
| [ci-speed.md](ci-speed.md) | full CI/E2E is the bottleneck: measure, set a target, levers, Playwright sharding rules |
| [upgrade-major-dependency.md](upgrade-major-dependency.md) | an update bot opens a major PR, an advisory, a radar review |
| [security-review.md](security-review.md) | before public exposure, after new input channels or incidents |
| [coder-hang-diagnosis.md](coder-hang-diagnosis.md) | the health check wakes the lead |
